# Database migrations

The current binary requires version 21. Version 15 records durable Stripe checkout attempts before provider creation and preserves accepted webhook outcomes and their ticket/attempt linkage for reconciliation. Version 16 adds lifecycle decision and external-action intent ledgers; it dispatches nothing. Version 17 adds workspace-scoped cultural import preview provenance, normalized candidates, safe parser errors and bounded canonical match hints; it stores no raw CSV and applies no canonical records.

`schema.sql` is the clean version-1 schema. The current binary requires version 21: version 2 adds canonical identities and rotating session families, version 3 removes the empty prototype session table, version 4 adds encrypted AT OAuth request/session persistence, version 5 adds durable revocation, version 6 adds opt-in transactional email delivery, version 7 adds signed feedback receipts and suppression, version 8 adds the minimal cultural model (profiles, places, protected place detail, event occurrences and multi-host occurrence credits; see `docs/development/cultural-model.md`), version 9 adds private event-to-public-occurrence links (see `docs/development/public-links.md`), version 10 widens workspace membership into a granular permission model and adds creator delegations (see `docs/development/authority-model.md`), version 11 adds the allowlisted AT record projection (`at_projection_records`, `at_projection_cursor`, `at_projection_quarantine`; see `docs/development/projection.md`), and version 12 adds the approved-authority allowlist and run ledger for projection backfill/rebuild/reconcile (`at_projection_authorities`, `at_projection_runs`; see `docs/development/projection.md`), version 13 adds verified channel consent grants and a send-time recheck (`consent_grants`, plus `purpose`/`workspace_id` on `email_outbox`; see `docs/development/consent.md`), version 14 adds one scoped announcement channel and delivery worker (`announcements`, `announcement_deliveries`, `consent_withdraw_tokens`; see `docs/development/announcements.md`), version 15 records durable Stripe checkout attempts, version 16 adds the private lifecycle decision/action ledger, and version 17 adds persisted review-only cultural import previews. Version 18 adds the private ended-event archive approval and correction ledger. Version 19 adds explicit import action and rollback provenance for selected canonical occurrences. Version 20 binds optional client purchase intents to durable checkout attempts and stores their accepted checkout URL. Version 21 adds a separate participant-shared requirements field to staffing items, defaulting to empty and independent of operator notes. Add later changes here as gap-free `NNNNNN_name.sql` files.

Version 13 is additive: one new table (`consent_grants`), two new nullable/defaulted columns on the existing `email_outbox` table (`purpose` defaults every existing and legacy row to `'transactional'`; `workspace_id` defaults null), and one widened check constraint on `email_outbox.delivery_status` adding `'withheld_consent'` to the existing set from version 6. No existing row's `delivery_status`, `purpose` or send behavior changes: `checkSendPermission` treats every `'transactional'` row exactly as before. Roll back by rolling back the application only; an old binary ignores the new columns and constraint value and keeps working against this schema, but must not be pointed at a database containing `'withheld_consent'` rows it does not understand as terminal.

Version 12 is additive: two new tables only, `at_projection_authorities` and `at_projection_runs`, neither referenced by any code path predating this change. `at_projection_authorities` gates which DIDs backfill/rebuild/reconcile may fetch from; `at_projection_runs` is an operational ledger (kind, authority, counts, outcome) with no record bodies. Roll back by rolling back the application; stop invoking `-backfill`/`-rebuild`/`-reconcile` on an old binary against this schema, since an old binary does not know about the new tables. No existing table, column or row changes.

Version 11 is additive: three new tables only, none referenced by any existing code path. It stores a read-only mirror of remote AT Protocol records for the three admitted collections; it never writes into the `cultural_*` tables. Roll back by rolling back the application and stopping the `atproto-projection` worker; the new tables stay unreferenced by older code.

Version 9 is additive: one new table, `event_public_links`, with a composite `(event_id, workspace_id)` foreign key back to the existing `events` table, matching version 8's pattern. No existing table, column, row or ticket/staffing/settlement behavior changes. Roll back by rolling back the application only; the new table stays empty and unreferenced by any older code path. Local operations (event editing, occurrences, tickets, staffing) never read this table on their hot path, so a rollback of this feature alone needs no data migration.

Version 8 is additive: new tables only, plus one `unique (id, workspace_id)` constraint added to the existing `events` table so occurrence rows can carry a composite foreign key that rejects a cross-workspace reference at the database level. No existing column, row or ticket/staffing/settlement behavior changes. Roll back by rolling back the application only; the new tables stay empty and unreferenced by any older code path.

Version 10 is additive: `workspace_members.role` widens from `('owner', 'member')` to `('owner', 'organizer', 'finance', 'door', 'crew', 'member')`; every existing row keeps its value and every existing literal `'owner'`/`'member'` call site keeps working, because `'member'` is kept as a permanent legacy alias with the same permissions as `'crew'` rather than being remapped. `expires_at`, `revoked_at` and `revoked_by_person_id` are added to `workspace_members` (all nullable, default absent, so existing rows are unaffected), and the new `creator_delegations` table is empty and unreferenced by any older code path. Roll back by rolling back the application only; do not drop the new columns or table while any revoked/expired membership or delegation record must be retained for audit.

Version 7 is additive. Disable sending before an application rollback; older workers do not enforce the new suppression ledger. Retain feedback and suppression records. Do not downgrade the database or enable an old worker against it.

Version 6 leaves all existing email rows held. An old binary also inserts held rows via the default. Roll back by disabling mail delivery/stopping the worker and rolling back the application while retaining this additive schema. Do not delete the delivery ledger or reset accepted/ambiguous messages to pending. Test migration from version 5 and full replay in disposable schemas before deployment.

Version 14 adds three tables: `announcements`, `announcement_deliveries`, and
`consent_withdraw_tokens`. Delivery rows reference the existing `email_outbox`
ledger; withdrawal tokens store only hashes and reference their consent grant.
An announcement/address uniqueness constraint prevents duplicate deliveries.

The previous binary requires schema version 13 and will reject version 14.
An application-only rollback is therefore insufficient: retain a recoverable
pre-migration database backup before deployment and stop both announcement and
mail workers before restoring it. Do not restore while sending remains enabled.

The application embeds these files, validates a gap-free sequence, hashes every migration, serializes runners with a PostgreSQL advisory transaction lock, and records successful applications in `schema_migrations`. Never edit an applied migration; add the next version.

Prototype compatibility is not automatic. Add a data migration only when a read-only inventory identifies real retained data and the migration has explicit acceptance and rollback evidence.

Versions 2 and 3 deliberately stop when prototype accounts or sessions are present. Inventory and explicitly approve any retained data before designing a migration; do not bypass these guards by deleting rows.
